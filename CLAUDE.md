# Personal Website — Project Guide

## About This Project

A public-facing personal website for James — a curated collection of ideas, topics, and things he finds interesting. The site will include interactive elements and pull in data from external sources (APIs, other websites). Content will be managed by editing files directly.

## James's Experience Level

James is new to coding. This shapes how we work together:

- **Explain decisions in plain English** — avoid jargon, or define it when you use it.
- **Explain errors clearly** — what went wrong, why it happened, and how to fix it.
- **Explain key principles** — when introducing a concept (e.g. how a browser fetches data, what a function does), give a brief plain-English explanation.
- **Present options before major decisions** — don't just pick a direction. Lay out the realistic choices, their trade-offs, and a recommendation, then let James decide.

## Tech Stack

### Current Direction
- **HTML / CSS / JavaScript (vanilla)** — no frameworks for now. This keeps things simple, teachable, and doesn't require build tools or a terminal to run.
- **GitHub Pages** — free static hosting, straightforward to set up, pairs well with a plain HTML/JS site.

### To Be Decided
The following involve real trade-offs and should be discussed with James before committing:
- Whether to introduce a JavaScript framework (e.g. React) as complexity grows
- How to handle data from external APIs — CORS considerations, whether a lightweight backend is ever needed
- Whether to use a static site generator if content grows significantly

## Hosting

**GitHub Pages** (free). Files are served directly from a GitHub repository. No server required, no cost.

## Coding Conventions

- Keep files simple and well-commented — comments should explain *why*, not just *what*.
- One feature / page at a time. Don't build ahead of what's been discussed.
- Prefer readability over cleverness — James should be able to read any code we write and understand it with a brief explanation.
